# SC03 延迟输出与浏览器帧生命周期

2026-09-04。本增量为 M1-03 / SC03 局部技术证据，不是 NX/TIA 输入、性能、异机或八小时验收。NX 用户样本及已保存测试副本未在本轮操作。

## 实现

- `scene-timeline.js` 保留每个 chunk 的不可变场景与序号，禁止重复/跳号提交；旧场景或同场景中落后于已呈现序号的回调都退休，不发送显示 ACK。关闭后清空关联并拒绝再提交。
- `frame-presenter.js` 统一持有/关闭 VideoFrame 与 JPEG 图像，取消时释放保留帧；已排队旧计时器与晚到回调不能改动新 run。诊断可显式延迟首个真实解码回调 3000ms，最多保留一个图像，其余解码继续。默认关闭，不用于性能结论。
- 收帧、排空及计时器均可检查保留帧期限，不能只依赖后台页面计时器。浏览器计时器通过保留 Window 接收者的包装调用。输出异常明确失败；呈现数加退休数必须等于解码数。
- JPEG 输出现在将图像所有权交给 presenter，不能在回调返回时立即销毁被延迟的图像。迟到解码、尺寸拒绝及输出异常仍释放，close 幂等。
- 取消期间异步控制连接/解码能力检查返回后，不再创建旧 run 的通道或解码器；旧 cleanup 不能改新 run 的按钮状态。此保护不是正式 Host/Agent epoch 状态机。
- 新增 `DesktopFixture --media-scenes`，每700ms显示/隐藏自身真实 owner 窗口，约119秒后自行退出；没有注入任何输入或假扮 NX/TIA。源为真实 WGC/GPU 场景，非截图回放。

## 可复现步骤

```powershell
. ./scripts/environment.ps1
& $Dotnet build tools/Workbench.DesktopFixture --no-restore
& $Dotnet tools/Workbench.DesktopFixture/bin/Debug/net10.0-windows10.0.19041.0/Workbench.DesktopFixture.dll --media-scenes
```

另一个终端运行 `./scripts/start-scene-version-probe.ps1`，浏览器打开 `http://127.0.0.1:8091/`，选择10秒、勾选首回调延迟，再开始。报告需检查 `presentation.delayed=1`、`staleScenes>=1`、呈现与退休总数和全量解码一致。只有普通媒体PASS但未产生旧场景退休时，不算该故障注入通过。夹具约119秒自动退出；已退出须重新启动和枚举，不能复用旧HWND。

停止该探针后用 `-Jpeg` 重复同一程序。取消/重连时保留取消报告，然后取消勾选延迟并重新开始，检查新流序号、场景及画面。服务器仅绑定loopback，网页无法改目标，也没有输入端点。

## 11:12 编码后延迟与主路重连增量
