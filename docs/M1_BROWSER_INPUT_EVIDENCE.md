# M1-02 F0 回环浏览器输入联调

日期 2026-09-04。此增量不放行 M1，不是 NX/TIA、LAN、正式鉴权或耐久验收。

## 已实现及限制

- MediaProbe 显式本机参数 `--input-fixture --owned` 才开放独立 `/control` WS。仅允许当前枚举的 F0 标题和受限进程类型；不接受网页指定 HWND、PID、路径或命令。普通启动继续只读。
- 精确 loopback IP、Host、Origin 校验；一条控制连接绑定一个租约、一条视频生命周期。旧视频回调持有原 Controller 引用，不能误操作重连后的控制者。队列、WS 消息、写入期限和实验时长有上限。
- 控制连接、视频断开或前端失焦走释放路径。WGC 完整合成 → 几何事务 → 编码帧发送记录 → 浏览器真正绘制 → 当前场景显示 ACK，之后才允许位置输入。局部画面实验仍无 Host/Agent 双进程隔离，卡死原生调用的外部 Guard 未完成。
- DOM Pointer Capture、左右中键、拖拽、滚轮、物理键与一次性 Unicode 提交。组合输入期间不同时发物理字符；中文先使用显式发送框。未实现全面 IME 控件兼容、保留系统键方案、输入图像标记或正式 React 前端。
- 原生前台由本地激活测试窗口。本机浏览器在后台工具页驱动 DOM，以免浏览器抢走原生前台；不能冒充第二台客户端。真实异机、双应用切换和激活策略仍待实现。

## 真实实验和修复

1. 第一轮约 34 秒，在网页视频中观察到真实 F0 点击、拖拽、F5 up、中键 up 与 wheel -120；回显 held keys/buttons 均空。右键展开时失败，未生成成功报告；当时旧服务只在成功时写报告，失败记录保留于本次工具输出及此说明。随后补了失败 JSON 落盘，不伪补原始报告。
2. 再次接入已有菜单时在首帧前失败，`artifacts/verification/media-probe/failed-20260904-095858-9604139.json`。定位到 `OwnedWindowScene.Arrange` 原先把 back-to-front 数组索引直接写进 native ZOrder，输入重新 Select 时反转了节点；修为 frontmost=0，并增加“重选不反转”“真实多节点快照进入输入事务”回归。执行器现在保留底层失效原因。
3. 修复后 `run-20260904-100110-8381974.json`：约 60 秒，44 编码/解码/呈现帧、6 个场景，15 条输入提交无拒绝。实际网页视频中依次观察到右键子菜单、点击后 `submenu-selected`、模态主窗禁用、模态文本变为 `浏览器中文，ABC 123`、远端 Escape 后 `modal-Cancel; text length=13`。这是自身夹具连贯操作，不是 NX 编辑框。
4. 同服务重连 `run-20260904-100241-4017976.json`：约 60 秒，91 编码/解码/呈现帧、5 个场景，12 条输入提交无拒绝。网页打开本机原生文件框，文件名栏显示 `测试中文文件名.txt`，点击取消后框消失，本机 F0 状态为 `native-open-Cancel`。没有打开、读取或保存选中文件。

两份成功报告包含实际 Intel Quick Sync、720p、avc1.42401F、浏览器 Chrome/152.0.0.0 与二进制哈希。帧数体现静止/交互场景，不是 30FPS 达标。firstOutputMs 不是输入延迟。输入 ACK 仅为提交结果；上述可见变化来自实际解码后的画面观察，两者分开记证据。

## 可复现运行

先在项目 PowerShell 中运行 `. ./scripts/environment.ps1`，构建后运行 `& $Dotnet tools/Workbench.DesktopFixture/bin/Debug/net10.0-windows10.0.19041.0/Workbench.DesktopFixture.dll --interactive`。另开 PowerShell 运行 `./scripts/start-input-probe.ps1`；它重新枚举唯一 F0，拒绝缺失或多实例，不沿用本文历史句柄。

用本机浏览器访问 `http://127.0.0.1:8091`，选择时长开始；必须保持 F0 原生前台。单机普通前台浏览器会与 F0 争抢焦点，这不是异机体验的有效替代。按页面说明进行安全自测，停止页面后 Ctrl+C 结束探针，并正常关闭 F0。不关闭 NX/TIA。不要把该 M1 入口映射至 LAN/CF。
