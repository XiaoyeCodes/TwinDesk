# M0-04.nx / SC04 的安全续接步骤

这是可运行的测试准备与人工核对说明。2026-09-04已在用户070.prt的隔离副本取得真实参数框和保存重开局部证据，见 [真实模型记录](./M1_NX_MODEL_EVIDENCE.md)；完整SC/M1验收仍未放行。项目浏览器目前只允许 F0 输入，以下 NX 本机操作不计为项目远控输入成功。

## 准备和边界

1. 保留 NX 已有工程，不强制关闭或保存任何用户文件。在安全的本机操作时段，确认只有一个 NX 主实例；如有未保存工程，先由用户决定如何处理。
2. 运行 `./scripts/start-nx-scene-probe.ps1 -PrepareOnly`，检查生成的 `artifacts/verification/sc04-nx-<时间>/preparation.json`。脚本重新枚举主窗、记录构建哈希并创建独立 `model` 子目录，不操作 NX、不启动媒体。多实例直接拒绝，不沿用历史句柄。
3. 在 NX 原生新建框选择毫米制建模模板，把新零件命名为 `N0_block.prt` 并放入本次 `model` 目录。只对该临时零件创建一个例如 40×30×20 mm 的简单块体或草图拉伸；记录实际创建方法、参数和 NX 版本。保存并重开后核对尺寸和特征树。许可或模板错误保留原始错误，不自动更改许可证。

已有用户授权样本时，可使用独立可写副本替代上述新建准备，记录原始哈希；不得直接编辑原件。若副本继承ReadOnly，先保留只读备份，仅把新测试副本设为可写。当前可复用本机 `artifacts/verification/nx-sample-20260904-102633-6240000/070-editable.prt` 的 `移动面 (71)`（距离1mm、角度0deg），续接前核对文件哈希与NX标题，不盲用历史窗口句柄。

## SC04 实际媒体核对

1. 停止其他8091探针，运行 `./scripts/start-nx-scene-probe.ps1`。这是只读采集；打开本机 `http://127.0.0.1:8091`，选择60秒，开始实际 WGC/GPU/H.264/WebCodecs 流。
2. 操作上述临时零件打开真正的特征编辑参数框。观察同一浏览器视频里模型、参数框完整可见，并记录该场景实际参数。取消编辑后确认框从视频中消失、主窗恢复。菜单、文件框的已有历史报告保留，不以截图补写流证据。
3. 本地用参数框改变一个尺寸、确认，再撤销；保存临时副本并重开核对。区分“本地 NX 可编辑”与“浏览器输入可编辑”，此阶段后者仍 NOT_RUN。
4. 完成有限时长流，让页面生成报告；记录 `media-probe/run-*.json` 实际构建哈希、编码器、源窗口/DPI、解码数量和场景变化。失败使用 `failed-*.json`，不能只取最后一个成功返回码。手工观察写入单独记录，包含操作者、时间和具体可见结果；不要篡改原始机器报告。
5. 停止只读媒体服务；正常处理本次临时零件。只保存测试模型，不覆盖原文件、不强制退出 NX。保留样本和失败证据供下一步 SC05 使用。

## 后续恢复点

SC04 完成后才把相关真实 NX 依赖放行，继续 M1-02/SC05 受限 NX 浏览器输入、右/中键、滚轮和文件/参数框操作。NX+F0 双路、JPEG、至少10分钟真实动态、1080p、异机与8小时均仍需单独实测。桌面工具不可用时可以由用户按以上步骤操作，代理继续安全代码任务，不伪报通过或缩减门槛。
