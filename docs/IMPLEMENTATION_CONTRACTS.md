# 实现契约、故障边界与任务依赖

版本 1.2 · 2026-09-03 · 配套 [主规划书](./CODEX_AUTOMATION_PLAN.md) 与 [验收标准](./ACCEPTANCE.md)

这些是待实现、待测试的工程约定，不是现有 API 文档。M1 可用最小探针验证能力；进入正式 M2 前冻结共享协议。变更本文件必须写明原因、影响与回归测试，不能默默让 C#、TypeScript 和验收标准各说一套。

## 1. 不得破坏的约束

1. 任意时刻只有一个有效控制租约、一个正常输入执行者和一个活动原生目标。租约属于浏览器连接，不仅属于账号。
2. 画面合成与输入命中共用不可变的 SceneGeometry。不能由前端猜源窗口偏移。
3. 每个按下动作都有正常释放、失焦释放及进程故障释放路径。释放不依赖视频编码线程。
4. 本机文件由原生软件读写。网页既不接收任意执行路径，也不充当原生文件权限沙箱。
5. 断线、网关停止、Agent 重启不关闭或重启用户工程进程，不自动重放原生编辑。
6. 弹窗完整性是主功能。若只能捕获主窗口而丢失保存框，不允许标记“应用已支持”。
7. 所有队列、消息、重试、缓存和日志都有上限。降级必须可见且可诊断。
8. 软件许可、系统兼容、实测性能是独立结论。能运行不等于厂商支持，编译通过不等于能建模。

## 2. 组件边界与数据所有权

| 数据/能力 | 唯一负责者 | 其他组件可以做什么 |
| --- | --- | --- |
| 认证、登录失败限速、会话撤销 | Host | Agent 只接受已验证的租约与本机 IPC |
| 应用配置 | 本机配置文件 + Host 校验 | 网页仅选择登记 appId，不修改 exe/启动参数 |
| 控制租约 | Host | Agent 验证租约代次、期限和心跳；前端显示持有状态 |
| 进程身份与窗口图 | Agent | Host 向浏览器发布不含 HWND 的实例摘要 |
| SceneGeometry/模态节点 | Agent | 前端等比显示并回传归一化位置，不重算原生布局 |
| GPU 纹理/帧池/编码器 | Agent 图形线程 | Host 仅转发压缩包，无原始帧 IPC |
| 正常键鼠注入 | Agent InputDispatcher | Host 不执行正常按下/移动，只做故障安全释放 |
| 故障释放账本 | Host InputSafetyGuard + Agent 本地集合 | 集合不保存输入正文，不作为审计键盘记录 |
| 解码/绘制/显示确认 | 前端媒体 Worker 与渲染模块 | Host 可监测队列和呈现延迟，ACK 不等于业务动作成功 |
| 工程内容 | NX/TIA 及本机文件系统 | 系统不解析、不迁移、不定时自动保存工程 |

Host/Agent 使用当前用户专属命名管道，附带协议版本和进程代次握手。启动凭据不得放 URL、日志或可被普通网页获取的接口。管道分为控制/状态和每路压缩媒体；限制最大帧和读取期限，循环读取到完整消息。拒绝未知版本和非本次启动的 Agent。

M2 定义以下共享模型，字段名以生成的协议为准：

| 模型 | 最少字段及含义 |
| --- | --- |
| HostIdentity | hostInstanceId（每次启动随机值）、protocolVersion、buildVersion |
| AppInstance | appId、instanceId、processStartTime、version、state、launchedByHost；PID/HWND 留在服务端 |
| ControlLease | leaseId、generation、connectionId、expiresAt、activeAppId；新接管必升代次 |
| SceneSnapshot | appId、sceneVersion、streamId、epoch、width/height、viewMode、modalNodeId、inputReady |
| SceneNode（内部） | nodeId、归属依据、HWND 身份、sourceRect、destinationRect、zOrder、clip、inputEnabled |
| StreamConfig | hostInstanceId、streamId、epoch、sceneVersion、codec、codecString、width/height、format、colorSpace |
| InputEnvelope | version、leaseId/generation、inputSeq、appId、sceneVersion、streamEpoch、displayedFrameSeq、type、payload |
| Operation | operationId、kind、state、appId、errorCode、correlationId；用于异步启动/关闭/重启 |

服务端不得信任浏览器提供的进程身份、窗口节点映射或“已经激活”声明。原生动作需要 ACK、状态确认与真实画面证据三个不同层次，不能混称成功。

## 3. 协议初始规范

### 3.1 控制与生命周期

- 应用状态变更 HTTP 操作需要身份、控制权、防伪令牌和 `requestId`。初始化/登录遵守各自引导规则；申请控制不要求预先持有租约，退出登录也不要求控制权。启动/关闭/重启返回 `202 + operationId`，状态通过控制 WS 推送；保存框等待不算 HTTP 请求超时失败。
- 连接顺序固定为：登录 → 建立已鉴权但无控制权的控制 WS → Host 返回 connectionId → 本会话经防伪 HTTP 请求 acquire(connectionId) → Host 绑定单租约 → 创建验证该租约的视频 WS。未获租约的控制连接只允许心跳/状态同步，不能输入。拒绝把另一登录会话的 connectionId 绑定到当前请求，接管须显式确认且先释放旧租约。
- `attach` 只接受已由服务端枚举得到的短期 instanceId；接入前重新核对进程路径、创建时间、用户会话与版本，不能用陈旧 ID 接入句柄重用后的窗口。
- 同一租约内 `requestId` 相同的生命周期请求返回同一 operation；同一 app 的冲突操作串行。去重缓存初始最多 128 项/10 分钟，有限清理。原生点击、按键、文本不做自动重试。
- inputSeq 为租约内严格递增整数，初始以安全整数范围定义；重复/乱序事件拒绝。越界、非有限数、超长数组、未知枚举拒绝并记录错误码，不打印消息正文。
- 坐标为当前显示内容内 `u,v ∈ [0,1]`。按下前必须持有当前场景首帧确认；epoch 不匹配也拒绝，避免同场景重建视频后仍点击旧画面。
- 默认仅租约拥有端订阅视频；另一标签页显示“被占用”并提供明确接管动作，不额外建立未受控观看会话。
- 旧场景/epoch 的 release 可清理当前租约自己的按下状态；旧租约的事件不得释放新租约正在操作的键。撤销时的全释放由服务端完成。
- WS 本身保证单连接消息顺序；跨控制、视频连接没有顺序保证，所以所有消息必须带代次，不能靠到达先后来关联。

建议业务错误码：

| 类别 | code | 恢复行为 |
| --- | --- | --- |
| 身份/租约 | AUTH_REQUIRED、AUTH_EXPIRED、CONTROL_BUSY、LEASE_STALE | 登录或显式申请控制，不自动夺取 |
| 原生环境 | APP_NOT_INSTALLED、APP_VERSION_UNVERIFIED、APP_START_TIMEOUT、APP_NEEDS_USER_ACTION | 展示配置/等待说明，不强杀 |
| 输入 | SCENE_STALE、STREAM_NOT_READY、FOCUS_DENIED、INPUT_PERMISSION_MISMATCH | 停新输入、释放、重新同步 |
| 媒体 | CAPTURE_UNAVAILABLE、ENCODER_UNAVAILABLE、DECODER_UNSUPPORTED、MEDIA_BACKPRESSURE | 有界恢复或显式兼容模式 |
| 桌面/进程 | DESKTOP_LOCKED、DISPLAY_CHANGED、AGENT_UNAVAILABLE | 暂停，满足条件后重新绑定 |
| 协议 | PROTOCOL_MISMATCH、INVALID_MESSAGE、MESSAGE_TOO_LARGE | 拒绝/关闭对应连接，不自动放宽限制 |

### 3.2 视频二进制包

一个完整 WS 二进制消息承载一个完整视频 access unit 或 JPEG；WebSocket 分片由接收循环重组后解析。包头固定 40 字节，大端序，字段偏移如下。

| 偏移 | 长度 | 字段 | 初始约定 |
| --- | --- | --- | --- |
| 0 | 4 | magic | ASCII `UGWB` |
| 4 | 1 | version | 1 |
| 5 | 1 | codec | 1=H264，2=JPEG |
| 6 | 2 | flags | bit0=独立解码关键帧；其余保留且必须为 0 |
| 8 | 4 | streamId | 由 Host 分配，与 app 绑定 |
| 12 | 4 | sceneVersion | 对应不可变几何 |
| 16 | 4 | epoch | 解码器重建代次 |
| 20 | 4 | frameSeq | epoch 内递增，不用时间戳代替 |
| 24 | 8 | timestampUs | epoch 内单调呈现时间微秒；读取用 BigInt 并作安全范围检查 |
| 32 | 2 | width | 实际输出尺寸，不是 CSS 宽度 |
| 34 | 2 | height | 实际输出尺寸 |
| 36 | 4 | payloadLength | 必须严格等于消息长度减 40 |

任一 32 位计数即将回绕时重建相应代次；Host 重启后用新的 hostInstanceId 区别旧流。每路首次发二进制帧之前，在该视频 WS 发送 StreamConfig JSON 文本消息。另允许 `streamAlive` 和下述 `sceneConfig` JSON；依据 WS 消息类型区分，禁止把其当作 JPEG/AVC 数据解码。`sceneConfig` 的次序与字段遵守第 4.4 节，不因几何变化反复用 StreamConfig 重置解码器。

H264 统一 Annex B，不传 AVCC `description` 冒充该格式；`codecString` 从实际 SPS 生成，不能固定一个可能不匹配的 profile。IDR 包必须包含解码所需 SPS/PPS；无 B 帧是低延迟初始配置，实际不支持则记录协商结果。浏览器必须 `isConfigSupported` 并处理运行期错误，不仅检测全局对象存在。[格式依据](https://www.w3.org/TR/webcodecs-avc-codec-registration/)

初始硬限制：控制消息 64 KiB，提交文本 4096 个 Unicode 标量，视频消息 8 MiB；尺寸必须非零、符合已协商档位且不超过 8192/边、总像素不超过 16,777,216。协商档位通常远低于该防御上限；不能靠接受超大分配修复尺寸 bug。

### 3.3 队列与静止画面

- 每路原始帧保留最新 1–2 帧；无积压时正常编码。已编码帧不随机丢 P 帧，改为新 epoch/IDR，必要时重建视频 WS。
- 每路发送缓存初始上限 16 MiB，任一发送超过 1 秒或显示持续落后进入背压处理；有界释放全部缓存。数值按 M1 数据调优并记录，不提高上限掩盖积压。
- 控制输入队列初始 256 项；连续 move 可合并，但不能跨按钮/键盘事件合并。离散事件排不下时撤销本轮控制并安全释放，不静默丢 keyup。
- 每路 `streamAlive` 初始 2 秒，客户端呈现反馈最多每秒 5 次；分别记录最近采集活动、最近场景变化、最近发送帧和最近显示确认。
- 静止、窗口有效、采集未报错、视频通道仍存活、无待显示更新时可继续使用最后画面；不能仅按“几秒没新帧”断言故障。
- 控制心跳正常但视频断开、待显示帧持续未确认、采集返回错误或窗口几何改变时，立即关闭该路 inputReady。场景没有更新但采集健康不确定时做有界重新绑定/验证，不能靠不断重发旧 JPEG 证明源仍正常。
- 新输入引发目标变化后若无法确认持续媒体进展，按媒体故障处理。静止 5 分钟后首次点击、仅视频断线、编码器卡住都必须单独测试。
- 光标选择单一呈现策略：默认服务端合成原生光标并隐藏画布内本地指针，避免两个光标。后续可独立传形状/热点，但不得重复合成，也不得把预测光标当作原生操作反馈。

## 4. 焦点、场景与输入安全流程

### 4.1 切换/弹窗事务

顺序必须是：冻结该路新输入 → 安全释放当前手势 → 更新窗口图/几何 → 发布新 sceneVersion → 建立/更新视频 → 浏览器显示当前代次的帧并确认 → 重新验证前台与窗口归属 → 开启输入。

- 对 CSS 尺寸变化，优先客户端等比缩放；需要改变源窗口才做几何事务，默认防抖 200 ms。模态弹窗/窗口关闭属于立即处理，不等防抖。
- 点击非活动面板先请求激活。若激活引发弹窗、尺寸或场景变化，第一次点击只激活不回放；画面就绪后用户重新点击，避免延迟执行旧位置动作。
- 检测目标最小化时进入 NEEDS_USER_ACTION，提供“恢复窗口”动作；用户恢复后重建场景。不承诺 Windows 最小化窗口持续渲染。
- NX 绘图区裁剪信息包含软件版本、DPI、主窗口尺寸、布局指纹。匹配失败回到完整界面并提示校准，不拿旧矩形继续建模。
- Windows 原生窗口可以在显示器内重叠；WGC 是否正常捕获被遮挡的软件必须实测。激活一侧后要确认它真实可点击，不能对后台窗口盲目全局注入。
- popup 节点可能属于辅助进程或系统托管窗口；只凭进程相同/不同都不足以确认归属。采用 owner、启动关系、前台事件、窗口类及显式适配规则，记录识别证据。不确定则提示并停止该场景操作。
- 显示输出补齐只允许目标已验证的可见区域。遇到无关遮挡时不传、不点；不自动移走用户其他程序来隐藏问题。

### 4.2 进程故障时谁松开按键

正常状态只有 Agent 执行输入。Host 的 InputSafetyGuard 仅持有保守的“可能按下”集合和故障释放能力：

1. Host 在转发 key/button down 前把它加入本租约账本；Agent 再完成自身校验、记录本地集合并注入。若未注入，Agent 明确回执用于清理账本。
2. Host 转发 up 后不能立即删账本；等 Agent 完成释放的回执才删。账本不记录字符输入正文，只保留释放所需键位/按钮与代次。
3. Host 崩溃/管道断开时，Agent 独立看门狗先使租约失效，释放本地集合，停止接受旧队列；用户应用继续运行。
4. Agent 退出时，Host 撤销租约、禁用新输入，确认该 PID+创建时间的旧 Agent 已退出，再由 Guard 释放账本。之后才可以启动新 Agent。
5. Agent 卡死时先断开旧会话，给有界退出期限；必要时只结束由本 Host 启动且身份核实的项目 Agent，确认退出后释放。绝不结束 NX/TIA。不得在旧 Agent 仍可能注入时先接纳新控制者。
6. Host 和 Agent 的故障检测/处置合计必须满足最迟 6 秒释放目标；M2/M6 在拖拽、修饰键按住时实测，而不是只测试“空闲崩溃”。

两个项目进程同时被强杀或系统整体失效没有存活组件可保证释放；记录限制并提供本机恢复步骤，重新启动前检查残留状态。不要为了掩盖该限制自行新增系统级特权服务。远控期间本机键鼠可能冲突，本地停止入口优先，不能声称完整区分所有实体键盘按下与注入状态。

### 4.3 中文与快捷键

区分物理快捷键事件与文本提交事件，二者不能对同一段 composition 重复发送。Unicode 输入按标量/UTF-16 代理对正确转换，测试中英文混合、标点和连续撤销。文本提交只发送一次，断线后提示核对原生输入框，不能重发整段。

NX 复位视角、适应窗口、隐藏/恢复等语义按钮维护“版本 → 已验证命令”的适配表。尚未验证的按钮禁用并解释；原生右键/快捷键仍可用。不要给所有 NX 版本硬编码同一个快捷键。

### 4.4 关联窗口捕获与帧版本契约

本节由真实 NX 文件菜单缺失证据触发，细化既有架构，不改变应用级控制边界。现有单窗口探针中的固定 `sceneVersion=1` 不是本节的实现。

**窗口准入与身份**

- 固定已接入的根 AppInstance；节点身份至少包含进程 ID/创建时间、用户会话、HWND 和本次窗口绑定代次。重复使用的 HWND 必须成为新节点，不能沿用旧纹理或输入目标。
- M1 首个增量选取根窗口与可验证 owner 链到根的同进程可见顶层窗口。owner 遍历检查重复、循环与消失；相同 PID 的无关窗口不能自动加入。
- 不把上述首个增量当作通用识别器。文件框、工具窗口可能由辅助进程/系统托管；随后通过显式适配与关联证据扩充。未能判断的活动弹窗进入待处理状态，禁止静默漏掉或改用整桌面流。
- 排除已关闭、最小化、DWM cloaked 节点；装饰阴影不具有输入目标身份。模态禁用、窗口层级和可点击区域均进入几何快照；不根据标题空/非空决定是否是菜单。

**物理边界与合成**

- 分别记录窗口矩形、客户区屏幕矩形、DWM 可见边界、WGC ContentSize/纹理尺寸。GetWindowRect 可能包含不可见边框且受 DPI 虚拟化影响，DWM 边界语义不同；不能无条件视为 WGC 的同一矩形。[Microsoft 边界说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindowrect)
- 首帧和每次尺寸/DPI 变化时确认纹理到屏幕物理像素的映射；如不一致，记录并重绑/校准，不靠拉伸旧纹理凑齐。计算使用有符号、检查溢出的坐标，包含负坐标与主窗口之外的弹窗。
- 默认按节点实际相对位置求场景联合矩形，空白处填确定背景。若联合范围过大，进入明确降级或用户选择的模态聚焦视图并重建几何，不能无提示裁掉对话框按钮。
- 图形与命中使用同一快照：GPU 从后向前绘制；输入从前向后选择真正可交互区域，排除禁用主窗、透明穿透区域和装饰节点。不能用透明像素的 alpha 值单独推断原生命中语义。
- 纯 CopySubresourceRegion 只可用于已验证的不透明、无需缩放的区域拷贝；它不提供透明混合或缩放。含透明/圆角节点时使用经测试的 GPU 混合及裁剪路径，并核对预乘 alpha；不支持时明确降级，不覆盖下层有效内容。[Microsoft GPU 拷贝说明](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11devicecontext-copysubresourceregion)
- 每应用初始最多 8 个内容节点，源纹理总像素与场景联合矩形各不超过 16,777,216，单边不超过 8192。超限先提示并停该场景输入，不任取前 8 个。它们是防御预算，可凭真实场景与显存测量修订，不是兼容性承诺。

**采集资源与静止源**

- 每节点有独立帧池/会话及有限最新帧缓存，合成复用同一 D3D 设备。若需要跨轮次保存内容，复制到明确拥有的 GPU 纹理；不能在 WinRT 帧释放后继续依赖其可能被复用的表面。
- 原始帧、合成表面和编码 sample 的所有权逐层明确。编码器仍持有纹理时不得覆盖重用；移除节点后取消回调、释放帧池及缓存，旧回调必须通过绑定代次校验。
- 新节点首帧未到时维持 inputReady=false，可保留旧画面并覆盖“场景更新中”提示。初始等待上限 2 秒，超时显示捕获失败；不能把没有弹窗的新几何标为完整。此期限可根据 M1 数据调整并记录。
- 节点出现/关闭/移位、裁剪、层级或模态状态变化必须触发重新合成，即使主窗口没有新像素帧。已关闭菜单不得持续停在画面上。
- 多节点源使用同一服务端单调时基生成合成呈现时间；保留各节点采集时间用于诊断，不能按每个节点的第一帧分别归零后混入一个视频流。

**不可变版本穿过异步编码与解码**

1. 合成提交时生成 frame descriptor，包含 streamId、epoch、sceneVersion、单调 timestampUs、输出尺寸及对应几何快照标识。版本此时绑定，不能在编码结果出来后读取可变 CurrentScene 重新贴标签。
2. 编码适配器通过受支持的时间戳/关联机制匹配输入 sample 与输出 access unit，保存有界在途映射；不得未经验证假定每次异步回调就是最近输入帧。重复/缺失时间戳、无法匹配、编码器重建时明确失败/恢复，禁止猜一个版本。M1 的在途上限初始为 8，实际能力变化须连同映射测试调整。
3. 输出大小、codec/SPS 及解码连续性不变时，可只增加 sceneVersion 并继续同一 epoch。服务端控制通道先冻结旧场景操作；视频通道在该版本第一帧前发送 `sceneConfig`，含 hostInstanceId、streamId、epoch、sceneVersion、width/height、viewMode、contentRect 和 modal 标记，不包含 HWND/原生绝对坐标。contentRect 为编码输出像素中的有效场景矩形，排除编码留黑边；它与浏览器 CSS 画面矩形分别处理，不能当作桌面坐标。前后端共享同一类型定义。
4. 浏览器将每个视频包的场景标记与该 chunk 的呈现时间关联，再在 VideoDecoder 输出回调取回。已过期的输出可以解码但不呈现、不确认、不启用输入，随后关闭 VideoFrame；不能随意丢旧 P 帧破坏仍沿用的解码参考链。
5. 只有当前目标场景的有效帧真正绘制后，才回传该 stream/epoch/sceneVersion/frameSeq 的显示确认。服务端比对当前快照并复核焦点后解除冻结。跨通道晚到的旧状态或 ACK 不能回退当前版本。
6. 如果编码配置、输出尺寸、时间基或参考连续性改变，升 epoch，发送新 StreamConfig 与独立可解码的 IDR/参数集；同步废弃旧映射、旧回调和输入许可。无法保持同 epoch 连续性的实现可明确走此恢复路径，不允许悄悄混帧。

探针可以仅实现媒体部分且不开放输入，但报告必须说明这一边界。上述规则不得用 UI 工具直接点击原生菜单的成功代替浏览器产品输入的验证。
