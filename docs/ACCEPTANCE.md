# 第一版验收标准与证据要求

版本：1.2 · 日期：2026-09-03 · 配套主文档：[技术架构与任务规划书](./CODEX_AUTOMATION_PLAN.md)、[实现契约](./IMPLEMENTATION_CONTRACTS.md)

本文所有性能数字均为设计目标，尚无实测通过结论。第一版不是只展示远程画面的演示程序；验收对象是可以打开、操作、编辑并保存真实 NX / 博图工程的工作系统。

## 1. 验收级别和样本

| 级别 | 场景 | 能证明什么 |
| --- | --- | --- |
| L0 | 协议、状态机、坐标算法测试 | 软件逻辑正确，不证明实际应用兼容 |
| L1 | Windows 测试夹具窗口 | 真实输入、窗口、图形管线和弹窗机制可工作 |
| L2 | 本机 NX 10.0.0.24 + 临时模型副本 | 当前 NX 的真实操作能力 |
| L3 | 安装就绪的 TIA Portal V21 + 临时工程副本 | 已记录组件/更新版本上的博图操作能力 |
| L4 | 第二台电脑 + LAN HTTPS / 用户 CF 域名 | 真实异机访问和对应网络路径可用 |

正式报告必须包含各层证据，不能用 L0 或 L1 替代 L2、L3、L4。

样本固定如下：

- F0：测试夹具，包含普通文本框、中文输入框、右键子菜单、模态对话框、可拖拽区域和编码的输入回显标记。
- N0：在临时目录创建简单 NX 零件，用于创建/修改特征、保存、重开。
- N1：用户典型模型或装配副本，记录文件哈希、源分辨率、本机直接操作帧率和规模描述；不要求把私有工程提交进仓库。
- T0：使用实际安装组件创建的离线 TIA 工程副本，可编辑块/变量并编译、保存；无需连接真实 PLC。
- T1：用户典型博图工程副本。若涉及旧工程升级，先保留原版本，由用户决定，不自动覆盖。

N1/T1 暂缺时可以完成基础工作流验收，但典型生产工程负载仍须标注未验证。相关测试不修改用户唯一原件。

## 2. 测试环境记录

每份报告记录：代码版本、构建配置、测试时间、OS 版本和版本号、DPI、显示器排列、源窗口尺寸、显卡/驱动、实际编码器、客户端浏览器版本与解码配置、NX/TIA 版本及组件、测试工程标识、网络路径、RTT/吞吐量、画质档位。

不能只写“Windows 11”“博图最新版”或“正常网络”。对于本机 Home 25H2 与博图组件兼容性，记录“厂商支持检查”和“本机运行实测”两个独立结论。

正式 LAN 性能基准：有线或稳定无线局域网，RTT ≤ 10 ms，可用带宽至少为配置总码率的 2 倍，1080p 标准档，源软件本地可以流畅运行。显示端安全上下文检测和 H.264 支持为真。

公网性能参考条件：实际 CF 路径 RTT ≤ 100 ms、可用带宽至少为总码率的 2 倍，无持续高丢包。网络不满足时仍执行功能/恢复测试，并报告实测值与条件；不能声称任意公网都满足指定延迟。

## 4. 性能和稳定性目标

以下是基于当前需求提出的验收目标，实施阶段不得为宣称通过而自行降低。

| ID | 指标 | 目标与测量范围 |
| --- | --- | --- |
| P01 | 已运行应用的首个可操作画面 | LAN ≤ 3 秒；CF 参考条件 ≤ 5 秒，从登录/控制申请完成到新场景首帧已显示；不含原生软件冷启动 |
| P02 | 1080p 动态刷新 | F0/N0 正常运动期间目标 30 FPS，60 秒窗口的实际显示帧率均值 ≥ 25；源软件负载与采集分开记录 |
| P03 | 双软件刷新 | 活动侧满足 P02；另一侧发生界面变化应在 LAN 500 ms 内显示；静态侧允许低帧率 |
| P04 | 输入到可见回显 | F0 单一客户端时钟测量 P95 ≤ 200 ms（LAN）；CF 参考目标 P95 ≤ 450 ms，报告样本量不少于 200 |
| P05 | 坐标准确性 | 1:1 夹具网格测试误差 ≤ 2 源像素；真实模型/控件 100 个代表目标无错选，不要求用户手动偏移瞄准 |
| P06 | 视图切换 | 已运行应用单双屏/绘图区切换后，LAN ≤ 2 秒恢复正确可操作画面；切换中无旧坐标误注入 |
| P07 | 断线/单进程故障保护 | 前端失焦/关闭立即尝试释放；网络丢失、Host 或 Agent 单独故障后，存活的安全模块最迟 6 秒释放并撤销租约 |
| P08 | 恢复连接 | 网络恢复且认证有效时，LAN ≤ 10 秒恢复正确画面；CF 报告实际值，不能包括仍处于网络不可达的时间 |
| P09 | 网关/Agent 资源 | 1080p 标准单路硬编，Host+Agent 占整机 CPU 均值目标 ≤ 20%，工作集合计目标 ≤ 1.5 GB；不包含 NX/TIA 自身 |
| P10 | 长时间资源趋势 | 8 小时试验，无无界队列；末小时稳态内存相较第一个完整稳态小时增加不超过 max(20%,100 MiB)；句柄/纹理数无持续单调增长 |
| P11 | 清晰度 | NX 尺寸标注、属性小字、TIA 程序与注释在相应画质/1:1 视图可读，无长期花屏或大面积黑块；保留源画面对比 |
| P12 | 输入可靠性 | F0 1000 次按下/释放、100 次窗口切换、20 次断线注入后没有残留按键和串软件输入 |
| P13 | 正式耐久 | 连续 8 小时，包括至少 2 小时间歇真实双软件操作和 6 小时混合活动/静止；无服务崩溃、工程丢失、永久黑屏 |

硬件编码无法启用时允许显示软件/JPEG 兼容模式继续排查，但不能因此自动免除正式使用的性能要求。若真实样本在本地已不流畅，记录本地瓶颈，分别报告原生性能和远程新增开销；不得要求传输层凭空提高原生软件帧率。

## 5. 正确测量延迟

分开记录以下数据：

1. 网络 RTT：心跳往返时间，只描述链路。
2. 服务端输入处理：接收消息到 `SendInput` 提交的耗时，只描述处理，不代表应用已响应。
3. 图形管线：捕获、编码、发送排队、浏览器解码与呈现排队。
4. 输入到可见回显：用户输入的效果通过真实画面返回浏览器后的时延。

F0 夹具接收到输入后，把 inputSeq 编成可从图像读取的标记；浏览器在实际解码/绘制得到该标记后，用自身 `performance.now()` 与输入发送时刻相减。此方法不依赖两台电脑系统时钟一致。报告名称为“输入至浏览器呈现回显”，不冒充显示器物理扫描的光子延迟。

NX/TIA 没有内置回显标记，采用短录屏/人工检查实际模型旋转、选中和文本显示反应；报告方法和观察限制。不得用 ACK、ping 或估算值冒充真实应用动作时延。若用跨机器时间戳相减，必须说明时钟同步方法与误差。

## 6. 故障注入和文件保护

必须覆盖：视频 WS 单独中断、控制 WS 中断、全部网络中断、Agent 崩溃、Host 退出、认证到期、浏览器标签页隐藏、原生软件正常退出、正在显示保存对话框、窗口尺寸/DPI 改变、采集设备失效。

涉及强制终止的测试只终止明确的测试组件或临时应用实例，不杀用户正在工作的 NX / TIA。保存/重启测试始终使用临时副本；真实 PLC 写入不属于自动测试。

8 小时耐久期间定时记录资源和状态，执行有界采样，不收集用户键盘正文或持续录制全部工程内容。若需要长时间自动运行，使用可中断的后台测试进程记录结果，检查进度时保持能回应用户，不能把工具调用永久阻塞。

补充边界测试：跨面板拖拽不能串到另一软件；最小化必须明确提示并能经恢复动作重建；静止不误判掉线；新场景尚未呈现时不能输入；无关窗口遮挡的屏幕补齐不得传出该窗口。所有故障测试均覆盖“正在按键/拖拽”而不仅是空闲状态。Host 与 Agent 同时被强杀的无存活看门狗限制，应如实列在运行手册，不在报告中扩张单进程容错的结论。

## 7. 报告格式与判定

每项记录：`ID / 环境 / 样本 / 执行步骤 / 期望 / 实际 / PASS|FAIL|NOT_RUN|WAITING_EXTERNAL / 证据位置 / 备注`。

- PASS 必须有证据；FAIL 保留失败原因及修复后的重跑结果。
- NOT_RUN 表示尚未执行，不等于不需要。
- WAITING_EXTERNAL 必须说明缺少的软件、授权、设备或网络条件，以及补齐后运行哪个测试。
- 条件项的缺失不能影响其余任务继续，但相关能力不写成“已验收”。

正式交付要求：A01–A28、A30–A34，P01–P13 在约定环境通过；用户已提供 CF 入口且确认 E10 时同时要求 A29。CF 的环境或使用条件缺失仍是公网未验收，不能把全项目标记完成。未具备全部环境时，只交付明确注明缺项的候选版本。主文档的全项目完成定义优先，不通过降低阈值或删除用例来结束目标。
