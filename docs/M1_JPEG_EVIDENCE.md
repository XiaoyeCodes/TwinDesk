# M1-03 JPEG 兼容路径增量

日期 2026-09-04。M1仍 IN_PROGRESS，SC06主项未放行；这是独立兼容分支，不是主技术路线变更。

## 实现

- 将 WgcOwnedNv12Source 的窗口采集/合成抽为共享步骤。H.264继续输出GPU NV12 sample；JPEG显式选择BGRA-only路径，无NV12转换或H.264编码器要求。两条路径使用同一owner准入、首帧门槛、几何版本与绑定生命周期。
- JPEG复用GPU合成后等比缩放和黑边，读回1280×720 BGRA。Windows BitmapEncoder以0.85质量编码，10Hz轮询上限，单帧限8MiB和2秒编码期限；没有变化的源不循环重发旧JPEG。报告单列CPU读回量，不能把此分支称为零拷贝。
- 本机显式 `--jpeg` /脚本 `-Jpeg`，没有静默改变默认硬编选择；无真实owned源、重复开关均拒绝。支持已有F0控制/显示ACK结构，但不开放NX/TIA输入或LAN。
- 浏览器createImageBitmap兼容解码不使用VideoDecoder。独立JPEG帧用codec=2及既有40字节头；绑定时间戳/场景版本，尺寸不匹配拒绝，最多2个在途解码，成功/失败/晚到图像均释放。既有HTTPS/同源边界不因JPEG降低。
